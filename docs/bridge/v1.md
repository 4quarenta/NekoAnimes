# NekoBridge v1

NekoBridge is the versioned contract between the trusted NekoAnimes SPA and the native shell.

## Security boundary

- Android exposes the bridge only to `BuildConfig.WEB_APP_ORIGIN` using AndroidX WebKit `addWebMessageListener`.
- Only main-frame messages are accepted.
- Native validates protocol version, method, route/identifier length and a 32 KiB message limit.
- Unknown methods fail closed.
- External origins must never receive bridge access.

## Envelope

SPA -> native requests always contain:

```json
{"version":1,"id":"uuid","type":"navigation.routeChanged","payload":{"route":"/anime"}}
```

Native direct replies use:

```json
{"version":1,"id":"uuid","type":"bridge.response","ok":true}
```

Native -> SPA events contain `version`, `type` and `payload` and do not require a request id.

## SPA -> native methods

- `bridge.handshake` `{ webVersion }`
- `navigation.routeChanged` `{ route }`
- `player.open` `{ episodeId }`
- `app.event` `{ name, placement? }`

`app.event` is semantic. The SPA reports product actions; the native shell owns platform-specific UI.

## Native -> SPA events

- `bridge.ready`
- `navigation.navigate`
- `player.closed`

## Capabilities

Android v1 advertises:

- `navigation`
- `player.open`
- `app.event`

New native features must be added as capabilities so an older shell and a newer remotely deployed SPA can negotiate safely.

## Versioning

Breaking protocol changes require a new integer bridge version. The native shell must reject unsupported versions rather than guessing behavior. The SPA must feature-detect through the handshake/capabilities before using optional native features.
